# Klaros — Gap Analysis (Current → Target)

Status: read-only analysis. No application code, schema, dependencies, environment variables, or deployment configuration were changed. Evidence baseline: `KLAROS_AI_CODEBASE_AUDIT.md` and its 7 companion `_CURRENT.md` documents, plus a direct-source verification pass (file:line citations below marked "(verified)" were re-confirmed by reading the actual file during this analysis, not merely carried over from the prior audit).

Format per row: **CURRENT** (what exists, with evidence) / **TARGET** (what the target architecture needs, per `KLAROS_TARGET_ARCHITECTURE.md`) / **GAP** / **PRIORITY** (P0/P1/P2/P3, see `KLAROS_IMPLEMENTATION_ROADMAP.md` §Priority) / **DEPENDENCIES**.

## 1. Foundational governance gaps (P0 — block any expansion of AI autonomy)

| # | Area | CURRENT | TARGET | GAP | PRIORITY | DEPENDENCIES |
|---|---|---|---|---|---|---|
| 1.1 | Autonomy enforcement | `Organization.autonomy_level` (`LEVEL_0`..`LEVEL_4`) is stored but **not read by any code path outside the model file itself** — its own in-code comment states "remains unenforced/decorative" (`backend/app/models/organization.py:60-67`, verified). Real gating today is per-tool `ActionPolicy` (`AUTO`/`APPROVAL_REQUIRED`/`BLOCKED`, `backend/app/tools/policy.py:11-14`) plus the `ai_paused` boolean kill switch, enforced inside `ToolRegistry.execute` (`backend/app/tools/registry.py:126-224`, verified) — not autonomy-level-based at all. | A real, enforced per-agent, per-tenant autonomy gate (`KLAROS_AI_AGENT_ARCHITECTURE.md` §Autonomy) that composes with (not replaces) the existing `ActionPolicy`/`TenantToolPolicy`/`ai_paused` mechanism. | The single biggest correction to any prior assumption that Klaros already has a working 0–4 autonomy scale: **it does not**. Any agent runtime built assuming `autonomy_level` is enforced will silently have no autonomy control. | **P0** | Must design before Phase 7 (Agent Runtime) writes a single line of execution code. |
| 1.2 | Multi-tenancy DB backstop | App-layer only; `TenantScopedMixin` on ~190/208 model classes, filtering via `CurrentUser.tenant_id` from JWT (`backend/app/api/deps.py:20,54`). No Postgres RLS anywhere (confirmed by grep across all migrations, both audit passes). | RLS (or an equivalent DB-enforced backstop) on every tenant-scoped table, especially all *new* Blueprint/Agent/Website/Marketplace tables. | A single missed `WHERE tenant_id=...` in any of ~70 service files (today) or any new service file (tomorrow) is a full cross-tenant leak with zero second layer of defense. | **P0** | `KLAROS_SECURITY_EVOLUTION_PLAN.md`; must land before Phase 1 introduces new tenant-scoped tables in volume. |
| 1.3 | No agent framework exists | Zero `class *Agent` definitions anywhere in `backend/app` (confirmed by grep, both passes). `AIExecutionService.request_tool_execution` (`backend/app/ai/execution_service.py:39-54`, verified) performs **no validation of its own** — it hardcodes `actor_type=ActorType.AI`, `actor_id=None` and passes straight through to `ToolRegistry.execute`; every real check (permission, tenant, kill-switch, policy) lives downstream, already shared with human calls. | `Agent`/`AgentVersion`/`AgentExecution`/`AgentToolPermission`/`AgentApproval` entity model (`KLAROS_AI_AGENT_ARCHITECTURE.md`) built *on* this boundary. | Building an agent runtime is 100% new work — there is no partial agent implementation to extend, only a clean, narrow, already-correct entry point to build on. | **P0** | Depends on 1.1 (autonomy) and a real per-agent tool allowlist (new `AgentToolPermission` table). |
| 1.4 | Tool-call loop/depth protection | **None found.** No recursion-depth counter, no per-call loop guard in `ToolRegistry.execute` (verified, `registry.py:126-224`). The only throttle is a monthly AI-usage billing cap (`BillingService.check_ai_usage_allowed`, applies only to `insights.generate_morning_brief`, the one tool flagged `counts_toward_ai_usage=True`). | Per-agent-execution step budget, wall-clock timeout, and duplicate-action detection (idempotency-key reuse across a single plan) before any agent can call tools in a loop. | An LLM-driven agent given multiple tool calls per turn has no existing backstop against infinite/runaway loops. | **P0** | `KLAROS_AI_AGENT_ARCHITECTURE.md` §Execution Limits. |
| 1.5 | Staging environment | No staging-vs-production separation beyond `ENV=development\|production` and per-integration `*_ENVIRONMENT=sandbox\|production` switches (verified via `docker-compose.prod.yml`, an override file only). | A real staging environment with isolated DB/Redis/Temporal namespace and test-mode third-party credentials. | Cannot safely test agent autonomy or website publishing against real-shaped data without a production-isolated environment. | **P0** | `KLAROS_DEPLOYMENT_EVOLUTION_PLAN.md` §4. |

## 4. Corrections to assumptions in the original audit brief

- **Autonomy levels are not a working 0–4 execution gate.** The brief's instruction to "not blindly assume a 0-4 Observe/Recommend/Prepare/Execute-approved/Execute-autonomous scale is correct" was well-founded: the enum exists with exactly those five doc-comment meanings (`LEVEL_0`..`LEVEL_4`, `organization.py:12-17`) but is never read by any executing code. The real, working autonomy-adjacent mechanism today is per-tool `ActionPolicy` (`AUTO`/`APPROVAL_REQUIRED`/`BLOCKED`) plus a binary `ai_paused` kill switch — a coarser, tool-level, not-agent-aware control. See `KLAROS_AI_AGENT_ARCHITECTURE.md` §Autonomy for the reconciled design.
- **`IntegrationConnection`'s status enum does not currently have `AVAILABLE`/`STUB` values** (it has `NOT_CONNECTED/CONNECTING/CONNECTED/ERROR/DISCONNECTED`) — the richer marketplace taxonomy in the target design is entirely new, not an extension of an existing enum.
- **The `frontend/app/automations/page.tsx` "mock" reference the original audit flagged as unresolved was checked directly in this pass and no longer exists** (`grep -rni mock frontend/app` returns zero matches repo-wide) — resolved, not a live concern.
- **`frontend/app/onboarding/page.tsx` is real and functional**, not a stub as the original audit left as UNKNOWN — it is a 4-step plan/timezone/free-text-knowledge/done wizard that writes to the Knowledge layer, confirmed by direct read.
